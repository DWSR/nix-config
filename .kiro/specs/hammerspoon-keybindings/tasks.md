# Implementation Plan

- [x] 1. (P) Package the signed Hammerspoon release as a Nix-installable app bundle
  - Fetch the pinned signed release archive by URL + sha256, then unpack and install the `.app` bundle verbatim (no resign or strip) so its Developer-ID signature and notarization stay intact.
  - Expose it as a buildable package attribute in the overlay so other layers can reference it.
  - Observable: building the package yields an app bundle containing a launchable `Hammerspoon` binary; a wrong or missing hash fails the build with an error naming the package.
  - Runs concurrently with Tasks 2.1 and 3.1 (separate boundary and files).
  - _Requirements: 1.1, 1.5, 1.8_
  - _Boundary: Hammerspoon Package_

- [x] 2. Build the pure keybinding renderer
- [x] 2.1 (P) Render a declarative keybinding set into Hammerspoon Lua
  - Turn a keybinding set (each binding = modifiers + key + exactly one action) into Lua that binds each hotkey globally and runs its action, mapping the three action types (AppleScript, command-line, inline Lua) to their Lua forms with safe string escaping.
  - Emit a config header that disables Sparkle auto-update and prompts for Accessibility, append any free-form extra Lua, and register a reload watcher keyed on the live config directory.
  - Observable: evaluating the renderer with a representative set (including a ⌃⌘⇧F12 inline-Lua binding) yields Lua containing the hotkey bind, the mapped action call, the header lines, and the reload watcher; an empty set yields a valid header-only config with no binds.
  - Independent of Tasks 1 and 3.1.
  - _Requirements: 2.2, 3.1, 3.2, 3.3, 3.4, 3.5, 3.6_
  - _Boundary: Lua Renderer_
- [x] 2.2 Reject invalid keybinding sets at evaluation time
  - Fail evaluation with an identifying message when two bindings share a hotkey, when a binding has zero or more than one action, or when a binding omits its key or uses an unsupported modifier or key.
  - Observable: evaluating each malformed set aborts with an error naming the offending binding/hotkey; a valid set evaluates cleanly.
  - _Requirements: 3.7, 3.8, 3.9_
  - _Boundary: Lua Renderer_

- [x] 3. Generate Hammerspoon API annotations for semantic checking
- [x] 3.1 (P) Port the EmmyLua annotation generator to standalone Lua
  - Reimplement the upstream EmmyLua.spoon generator as a plain Lua script that reads a Hammerspoon `docs.json` and emits one LuaCATS `---@class hs.<module>` file per module, with no dependency on a running Hammerspoon.
  - Observable: running the generator against a `docs.json` fixture emits LuaCATS files declaring `hs` and at least one `hs.<module>` class.
  - Independent of Tasks 1 and 2.
  - _Requirements: 5.2, 5.4_
  - _Boundary: Hammerspoon Annotations_
- [x] 3.2 Produce the annotation set from the pinned bundle
  - Add a build artifact that runs the generator over the packaged bundle's `docs.json`, yielding a directory of `hs` LuaCATS annotations that tracks the pinned Hammerspoon version.
  - Observable: building the annotation artifact yields a directory of `hs.*` annotation files derived from the packaged bundle.
  - _Depends: 1, 3.1_
  - _Requirements: 5.2, 5.4_
  - _Boundary: Hammerspoon Annotations_

- [x] 4. Gate the delivered config on Lua syntax
  - Wrap the renderer in a build step that writes the generated config and runs a Lua 5.4 parse check (using the Lua toolchain as a build input), emitting the validated config file as its output; this step runs on every rebuild.
  - Observable: building the gate on a valid config yields a non-empty config file; building it on a config whose extra Lua contains a syntax error fails the build with the parser's error.
  - _Depends: 2.1_
  - _Requirements: 3.4, 5.1, 5.3, 5.5_
  - _Boundary: Config Syntax Gate_

- [ ] 5. Add the hermetic semantic validation check

  - Observable: building the check on a valid config succeeds; building it on a config that references a nonexistent `hs` symbol fails with an undefined-field/global diagnostic; it runs with no network and no running Hammerspoon.
  - _Depends: 2.1, 3.2_

  - _Boundary: Semantic Validation Check_

## Implementation Notes
- Task 1: `stdenvNoCC.mkDerivation` unpacking a single-`.app` zip needs `sourceRoot = "."`, else stdenv `cd`s into `Hammerspoon.app` and the verbatim `cp -R Hammerspoon.app $out/Applications/` fails. `dontFixup`/`dontStrip` keep the Developer-ID signature + notarization intact (verified via `codesign --verify`). Use the SRI hash form (`sha256-EbsckPr1Qn83x71P5+q5d0rkPh1csCDFswiNrDKEnvo=`) to match repo convention. The built bundle (`pkgs.hammerspoon`) exposes `Contents/Resources/docs.json` (consumed by Task 3.2) and `Contents/MacOS/Hammerspoon` (the launchd-agent target for Task 6.3).
- Build/eval any custom package via: `nix build --impure --expr 'let f = builtins.getFlake (toString /Users/brandonmcnama/src/github.com/DWSR/nix-config); pkgs = import f.inputs.nixpkgs { system = builtins.currentSystem; overlays = [ f.outputs.overlays.unstable-packages f.outputs.overlays.custom-packages ]; }; in pkgs.<attr>'`.
- Commits are SSH-signed via 1Password (`op-ssh-sign`); git-mcp commits succeed only if the 1Password prompt is approved within the MCP request window. Bash `git commit` cannot sign inside the sandbox.
- Task 2.1/2.2: renderer is `home-manager/common/hammerspoon-keybindings/render.nix` = `{ lib }: cfg: string`; consumed by Tasks 4/5 gates and Task 8.2 tests as `import ./render.nix { inherit lib; }`. Validation (`throw`s for 3.7/3.8/3.9) lives in the renderer (host-free `nix eval` surfaces failures); hotkey identity = `sort(mods) ++ [toLower key]`.
- Task 4 ALERT (flagged during 2.1): in `nixpkgs#lua5_4` (Lua 5.4.7) the parser binary is named **`luac`**, NOT `luac5.4` as design.md/the validation memory assume. Task 4's syntax gate must invoke `luac -p` (or verify the exact binary name shipped by the flake-pinned nixpkgs `pkgs.lua5_4`). `pkgs.lua5_4` is the right package; the binary name is the gotcha.
- Task 3.1/3.2: generator `overlays/hammerspoon/gen-emmylua.lua` is self-contained (vendored rxi/json.lua decode, MIT; needs only the `lua` interpreter; does NOT mkdir its out-dir). `hammerspoonHsAnnotations` (overlays/misc.nix) = `runCommand` that `mkdir -p $out` then runs the generator over `${final.hammerspoon}/Applications/Hammerspoon.app/Contents/Resources/docs.json` → 140 `hs.*.lua` files, version-tracking by construction. Proven (3.1 + 3.2 reviews) to drive LuaLS member-checking: valid `hs.*` → exit 0; `hs.bogusModule.foo` → exit 1 `undefined-field`.
- CRITICAL (caught in 3.2 review): `gen-emmylua.lua` MUST be git-tracked. Nix only includes tracked files on a CLEAN-tree eval (CI / `nix flake check` / fresh clone); an untracked generator makes `${./hammerspoon/gen-emmylua.lua}` resolve to nothing and breaks both `hammerspoonHsAnnotations` and the Task 5 semantic check. (Committed in the Task 3 commit.)
- Task 5 gate: LuaLS 3.18.1 surfaces `undefined-field`/`undefined-global` via stdout + NON-ZERO exit but writes NO `check.json` to `--logpath`. Key the gate on the EXIT CODE (treat "check.json absent" as the no-diagnostics/pass case).
