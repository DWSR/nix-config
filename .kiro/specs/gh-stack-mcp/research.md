# Research: gh-stack-mcp

Source review only: no `gh stack` command, live Stack API mutation, or host-runtime test was performed. This repo has no `product.md`, `tech.md`, or `structure.md` steering files; `brief.md` and the existing MCP modules supply the feature context.

## Summary

Complex integration with a new server, a shared CLI pin, two host registrations, and agent-policy migration. The CLI's human-output and implicit-remote paths drive the validation and result boundaries below.

## Research log: external findings

- The locked unstable package is v0.1.0 (`flake.lock:609-623`; [nixpkgs recipe](https://github.com/NixOS/nixpkgs/blob/c27cdad491a991b11ed731760aa2ef8db0cb0410/pkgs/by-name/gh/gh-stack/package.nix#L9-L23)). [v0.1.1 changes](https://github.com/github/gh-stack/compare/v0.1.0...v0.1.1) fix remote Stack pagination and absent-trunk handling; `view --json` shape stays the same. Both tags are MIT-licensed; upstream publishes Darwin ARM and AMD binaries.
- `gh-stack` runs directly as `gh-stack <command>` from the Nix package. The official [Go MCP SDK v1.8.0](https://github.com/modelcontextprotocol/go-sdk/blob/v1.8.0/docs/quick_start.md) has stdio/typed-tool support, is actively maintained, and requires Go 1.25; [gh-stack v0.1.1](https://github.com/github/gh-stack/blob/v0.1.1/go.mod#L1-L4) and [v0.1.0](https://github.com/github/gh-stack/blob/v0.1.0/go.mod#L1-L4) both require Go 1.26. SDK source is Apache-2.0/MIT; no license incompatibility was found. A wrapper invoking an independent binary need not import the extension's Go module.
- `view --json` refreshes PR state and [can write local Stack metadata](https://github.com/github/gh-stack/blob/v0.1.1/cmd/view.go#L61-L136). It returns a locally tracked trunk, current branch, and ordered branches, not a remote Stack number or remote list.
- The extension derives repository identity from cwd/Git remotes or `GH_REPO`. Its [PR URL parser discards host, owner, and repo](https://github.com/github/gh-stack/blob/v0.1.1/cmd/utils.go#L1349-L1368), so a foreign URL can address a same-numbered PR in the current repository. `--remote` selects a Git remote, not the API repository ([selector](https://github.com/github/gh-stack/blob/v0.1.1/cmd/utils.go#L1409-L1432)).
- `checkout` tries numeric targets as Stack, then PR, then branch; `link` can interpret its first numeric target as an existing Stack and append to it ([checkout](https://github.com/github/gh-stack/blob/v0.1.1/cmd/checkout.go#L116-L225), [link](https://github.com/github/gh-stack/blob/v0.1.1/cmd/link.go#L160-L173)).
- Remote branch-name checkout and missing-trunk init choose a Git remote from branch/default settings **before** falling back to a sole remote; neither accepts `--remote`, and `GH_REPO` pins only the API target ([checkout import](https://github.com/github/gh-stack/blob/v0.1.1/cmd/checkout.go#L312-L334), [selection](https://github.com/github/gh-stack/blob/v0.1.1/internal/git/gitops.go#L234-L269), [init](https://github.com/github/gh-stack/blob/v0.1.1/cmd/init.go#L135-L155)). A single-remote count alone does not prove the CLI's effective selection equals the validated remote. Noninteractive init skips the optional `rerere` configuration prompt ([init](https://github.com/github/gh-stack/blob/v0.1.1/cmd/init.go#L59-L75)).
- `GH_REPO=HOST/OWNER/REPO` pins the Stack API target independently of the Git remote ([go-gh resolution](https://github.com/cli/go-gh/blob/v2.13.0/pkg/repository/repository.go#L47-L64)). PR creation supplies an unqualified head branch, so fork push plus upstream PR base is [not reliably supported](https://github.com/github/gh-stack/blob/v0.1.1/internal/github/github.go#L99-L123).
- Headless `init` needs explicit branches; `add` needs a branch or message on an existing Stack. `add -A/-u` without `-m` can open a Git commit editor ([add implementation](https://github.com/github/gh-stack/blob/v0.1.1/cmd/add.go#L345-L352)); Git signing and hooks remain in force. `submit --auto` avoids its editor, but a [pending modify can trigger remote unstack without confirmation](https://github.com/github/gh-stack/blob/v0.1.1/cmd/submit.go#L627-L675). `merge` also skips confirmation when no terminal is attached ([merge implementation](https://github.com/github/gh-stack/blob/v0.1.1/cmd/merge.go#L162-L190)).
- Rebase conflicts may leave [`<git-dir>/gh-stack-rebase-state`](https://github.com/github/gh-stack/blob/v0.1.1/cmd/rebase.go#L29-L45) for `--continue`/`--abort`; exit 3 alone does not prove the marker was saved. Sync instead restores affected refs after its own cascade conflict. Abort may only partially restore refs ([recovery](https://github.com/github/gh-stack/blob/v0.1.1/cmd/rebase.go#L481-L543)).
- The rebase marker has no repository/remote identity, is written [non-atomically](https://github.com/github/gh-stack/blob/v0.1.1/cmd/rebase.go#L518-L539), and the CLI accepts a JSON `{}` marker until recovery logic fails. `--abort` can hard-reset saved branch refs without an active Git rebase ([recovery](https://github.com/github/gh-stack/blob/v0.1.1/cmd/rebase.go#L481-L504)).
- In a linked worktree, the metadata and recovery markers live under its per-worktree Git directory, not the `.git` pointer file ([Git worktree](https://github.com/git/git/blob/v2.45.0/Documentation/git-worktree.txt#L343-L358)). A `gh-stack-modify-state` marker with `pending_submit` can cause headless `submit --auto` to unstack an earlier remote Stack ([submit recovery](https://github.com/github/gh-stack/blob/v0.1.1/cmd/submit.go#L623-L679)).
- `sync` attempts [one atomic multi-branch push](https://github.com/github/gh-stack/blob/v0.1.1/cmd/sync.go#L235-L253); standalone `push` is [non-atomic](https://github.com/github/gh-stack/blob/v0.1.1/cmd/push.go#L100-L113), while submit pushes branches sequentially. A [headless divergence returns exit 0 without syncing](https://github.com/github/gh-stack/blob/v0.1.1/cmd/sync.go#L121-L137); sync/submit/link can also warn and continue on some partial failures. Remote unstack can leave locked members, and merge queue acceptance is not a completed merge ([unstack](https://github.com/github/gh-stack/blob/v0.1.1/cmd/unstack.go#L225-L237), [merge](https://github.com/github/gh-stack/blob/v0.1.1/cmd/merge.go#L386-L398)).
- On these hosts, `gh auth login` is provisioned from an existing secret; `MCP_GITHUB_TOKEN` is routed to GitHub MCP but is not `GH_TOKEN` for the extension (`scripts/mcp-secrets-activate.nix:243-275`, `home-manager/mcp/default.nix:417-441,499-507`). The extension's go-gh library can invoke `gh auth token` using `GH_PATH` or PATH; launchd does not provide a reliable Nix `gh` path ([go-gh auth](https://github.com/cli/go-gh/blob/v2.13.0/pkg/auth/auth.go)). Existing global Git signing uses 1Password; the git-mcp-only Secure Enclave signer does not reach this new upstream (`home-manager/common/git.nix:16-33`, `home-manager/mcp/default.nix:398-415`).
- The proxy binds `127.0.0.1` with `require_mcp_auth = false` (`home-manager/mcp/default.nix:549-565`). **Any process that can reach the loopback port, including another local account, can call tools without an agent prompt.** Loopback is not same-user isolation.
- mcpproxy v0.67.0 derives `call_with` from explicit `destructiveHint` and `readOnlyHint` ([classifier](https://github.com/smart-mcp-proxy/mcpproxy-go/blob/v0.67.0/internal/contracts/intent.go#L199-L228)). The read/write proxy calls reject tools only when `destructiveHint: true`; [code execution can dispatch nested tools](https://github.com/smart-mcp-proxy/mcpproxy-go/blob/v0.67.0/internal/jsruntime/runtime.go#L452-L505) without OpenCode's destructive-tool prompt. OpenCode `ask` can be persistently approved or bypassed with auto mode ([permission handling](https://github.com/anomalyco/opencode/blob/v1.18.32/packages/opencode/src/permission/index.ts#L142-L151)). The local budget validator lacks a `mcpproxy_code_execution` permission key (`scripts/subagent-context-budget.js:38-67`).
- The pinned proxy has a **global** [`call_tool_timeout=2m`](https://github.com/smart-mcp-proxy/mcpproxy-go/blob/v0.67.0/internal/config/config.go#L1722-L1733), no per-server equivalent; OpenCode's MCP tool-call default is 60s unless its existing entry sets `timeout` in milliseconds ([config](https://github.com/anomalyco/opencode/blob/v1.18.32/packages/opencode/src/mcp/index.ts#L661-L685)). The proxy HTTP `/mcp` handler clears the response write deadline; a separate proxy would isolate timeouts but add another service and entrypoint.
- [`FindPRForBranch`](https://github.com/github/gh-stack/blob/v0.1.1/internal/github/github.go#L98-L144) takes the first open PR with a matching branch name, regardless of head repository. `view`, `init`, `sync`, `rebase`, `push`, `submit`, and `link` can adopt that PR locally; `sync`, `submit`, and `link` can later change remote Stack/PR state. GitHub MCP's paginated open-PR listing exposes head/base repositories but is only an **agent-side** guard.

## Architecture options and risk

- **Extend the patched GitHub MCP:** Reuse its Stack API and tool registry, but couple local CLI state to the upstream-patch lifecycle and Go module; changes exceed its remote-only ownership.
- **New Go server + per-host `extraServers`:** Isolate local CLI semantics and reuse existing registration/check patterns; requires one shared v0.1.1 extension pin and two host declarations.
- **New Go server + shared Home Manager module:** Avoid duplicated registrations; adds a new config abstraction for one server and touches central module composition.

Effort **L** (1–2 weeks); risk **High**: multi-branch mutations, noninteractive prompts, silent partial success, authorization limits, and multiple policy copies.

## Synthesis findings

- All ten included commands share worktree/repository validation and a noninteractive subprocess lifetime. Mutations share an unverified-write result; only view supplies structured observations.
- Only `view --json` provides structured local data; remote mutation postconditions belong to fresh GitHub MCP/Git-MCP reads, not human-output parsing in the wrapper.
- The official SDK supplies MCP transport and schema validation; the pinned CLI supplies Stack semantics. A second remote Stack client would duplicate the existing GitHub MCP except for the explicitly deferred merge preflight.

## Implementation verification backlog

- Verify the pinning expression/build hashes and Darwin Go toolchain for v0.1.1 plus the chosen SDK; ensure one derivation feeds both the CLI extension and wrapper.
- Verify same-repository identity validation for multiple remotes and inherited `GH_REPO`; check authentication through existing `gh` auth state without assuming `MCP_GITHUB_TOKEN` is `GH_TOKEN`.
- Verify effective captain permission precedence, code-execution denial in both config variants, classification/dispatch of every new tool, and the shared proxy/OpenCode timeout ordering; do not treat OpenCode approval as backend authorization.
- Test bounded subprocess lifetime/output, pending-modify/rebase guards, and GitHub MCP/Git-MCP postflight; no timeout proves absence of remote mutation.
- Verify `/restack` stays in its invoking agent and helper permissions remain read-only. Real-host auth/signing behavior and target-repository Stacks availability remain untested.
