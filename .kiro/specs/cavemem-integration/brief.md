# Brief: cavemem-integration

## Problem

The current Obsidian-backed memory system imposes a heavy, manual workflow on
every agent session: a 21-line memory-creation rule block, mandatory startup
checks, transcription-after-every-exchange, periodic summarization, and
search-before-write deduplication. ~243 of the 264 lines in
`home-manager/common/agents.md` are memory rules. This burden has produced
459 .md notes since 2026-04-11, but it also means agents spend significant
context budget and attention on memory bookkeeping rather than the user's
actual task. There is no ambient capture: if an agent fails to transcribe,
that conversation is lost; if it skips summary updates, only the transcript
remains; if it doesn't search before writing a memory, duplicates accumulate
(empirically observed: `yugabyte` 33 / `yugabytedb` 26 / `globaldb-yugabyte` 69).

The 2026-05-09 cavemem investigation identified cavemem as the right tool to
absorb the ambient-capture concern (hooks-based automatic observations,
SQLite + FTS5 + vector hybrid search), but deferred integration because of
upstream bugs. The 2026-05-13 re-check confirmed those bugs remain open;
upstream maintainer responsiveness is slow (PRs unreviewed 4-13 days). Waiting
indefinitely is not a viable plan.

## Current State

- **Memory system**: Obsidian-only. AGENTS.md mandates Obsidian for
  transcription, summary, AND memory writes. mcp-obsidian server is
  HM-managed (`overlays/mcp-servers.nix` builds Piotr1215/mcp-obsidian@c99c064;
  `home-manager/mcp/default.nix` wires it via mandatory `home.mcp.obsidianVaultPath`).
  Vault paths are Shopify Google Drive and personal iCloud.
- **opencode integration**: opencode.json is generated declaratively by HM
  via `programs.opencode.settings`. The opencode wrapper hard-fails on
  obsidian MCP health-check (similar pattern needed for cavemem).
- **Existing notes inventory**: 259 memory notes, 111 transcription notes,
  91 summary notes, 6 MOCs (per vault-curator baseline).
- **Cavemem upstream**: v0.2.1 (2026-05-06). Bugs #14, #25, #39 unreleased
  fixes exist on main and in upstream PRs; bug #28 closed unfixed.
  pr0d1r2/nix-cavemem stale at v0.1.3, no HM module.
- **Existing scripts pattern**: `scripts/cc-sdd-init.nix`, `scripts/mcp-sync-from-1password.nix`,
  `scripts/mcp-verify-secrets.nix`, `scripts/sqlite-backup-cli.nix` —
  Nix-packaged bash/Node wrappers exposed via the overlay.
- **Existing subagent pattern**: `home-manager/common/agents/vault-curator.md`
  is the model — frontmatter declares mode/model/permissions, body is the
  agent definition. Loaded via opencode's `agent` plugin pattern.

## Desired Outcome

When this spec is done:

1. `cavemem` is available on PATH on both Shopify and personal hosts via
   the overlay, built from our patched v0.2.1 source.
2. `cavemem mcp` is registered in mcphub `servers.json` declaratively;
   opencode wrapper hard-fails if cavemem MCP is unreachable.
3. Cavemem's settings.json is HM-managed (declarative, idempotent across
   rebuilds). Embedding provider is configurable via HM options; default is
   local Xenova/all-MiniLM-L6-v2.
4. The opencode plugin file (`~/.config/opencode/plugins/cavemem.js`) is
   shipped via `xdg.configFile` from a vendored, patched source — NOT
   generated by `cavemem install`.
5. opencode.json's `mcpServers.cavemem` entry is declared via `programs.opencode.settings`,
   alongside the existing entries; no imperative installer touches it.
6. The three patched bugs (#14, #39, #25) are verifiable: a smoke-test runs
   a fake opencode session, queries cavemem, and confirms (a) observations
   save non-empty input/output, (b) cross-project session-start does not
   leak, (c) `search.alpha` docstring matches code semantics.
7. AGENTS.md is restructured: transcription and summary write rules are
   REMOVED (cavemem is the canonical source); memory write rules are KEPT
   (curated knowledge stays in Obsidian). Cross-references explain the new
   split clearly.
8. `home-manager/common/agents/vault-curator.md` is updated to reflect that
   transcription/summary no longer come from agents (no agent writes to
   `conversations/transcriptions/` or `conversations/summaries/` after this
   ships).
9. A one-shot Node-based importer (`scripts/cavemem-import-vault.nix` or
   similar) is packaged that reads existing `.md` transcription and summary
   notes and INSERTs equivalent rows directly into `cavemem.db` via
   better-sqlite3, bypassing the broken `cavemem import` CLI. The importer
   is idempotent (re-running doesn't duplicate; uses content-hash dedup).

## Approach

Vendor + patch + custom HM module. Specifically:

1. **Overlay** (`overlays/cavemem.nix` or extend `overlays/mcp-servers.nix`):
   `buildNpmPackage` against patched cavemem v0.2.1 source. Patches applied
   from upstream PRs:
   - PR #31 / commit f2e2f49: bug #14 fix (opencode hook plugin: payload-shape
     correction so input/output are not empty)
   - PR #21: bug #39 fix (one-line cwd filter in session-start handler)
   - PR #31 partial: bug #25 fix (Zod docstring on `search.alpha` inverted)
   Patches applied via Nix `patches = [ ./patches/...patch ]` so they're
   reviewable and version-pinnable.
2. **HM module** (`home-manager/common/cavemem.nix`):
   - `home.cavemem.enable`: bool
   - `home.cavemem.dataDir`: path (default: `${config.xdg.dataHome}/cavemem`)
   - `home.cavemem.embedding.provider`: enum [`local` `ollama` `openai` `none`]
     (default `local`)
   - `home.cavemem.embedding.model`: str (default `Xenova/all-MiniLM-L6-v2`)
   - `home.cavemem.embedding.endpoint`/`apiKey`: optional, for non-local providers
   - `home.cavemem.compression.intensity`: enum (default `medium`)
   - Generates `${dataDir}/settings.json` via `home.file` with all options
     interpolated
   - Generates `~/.config/opencode/plugins/cavemem.js` from a vendored,
     patched source via `xdg.configFile` (NOT via `cavemem install`)
   - Adds `cavemem` to `home.mcp.extraServers` (or equivalent) so mcphub
     picks it up
   - Adds `mcpServers.cavemem` to `programs.opencode.settings.mcpServers`
3. **opencode wrapper hard-fail**: Extend `home-manager/common/opencode.nix`
   health check (currently checks obsidian, lines 38-46) to also probe
   cavemem MCP. Refuse to start opencode if cavemem MCP is unreachable
   (matches the pre-existing obsidian invariant).
4. **AGENTS.md restructure**: Replace the Transcription and Session Summary
   sections with a single "Ambient capture (cavemem)" pointer that explains
   transcription/summary are now automatic via cavemem hooks. Keep the
   Memory Recall, Memories, Obsidian Tool Reference, and Tag Guidelines
   sections intact. Add a note about the cavemem MCP tool availability.
5. **vault-curator.md update**: Remove statements that imply agents write
   to `conversations/transcriptions/` or `conversations/summaries/`. Note
   that those directories now hold archived/migrated history only and
   should not be modified by curation passes. Update "Vault topology"
   section accordingly.
6. **Custom importer**:
   `scripts/cavemem-import-vault.nix` packages a Node script that:
   - Walks `<vault>/conversations/transcriptions/*.md` and
     `<vault>/conversations/summaries/*.md`
   - Parses frontmatter (YAML) for date/session/project tags
   - For each transcription, INSERTs into `sessions` (id, ide=`obsidian-migration`,
     cwd=`<unknown>`, started_at, ended_at, metadata={migrated: true}) and
     for each ## Exchange, INSERTs into `observations` (kind=`prompt`/`response`,
     content, compressed=null, ts derived from session date)
   - For each summary, INSERTs into `summaries` (session_id, scope=`session`,
     content)
   - Uses content-hash dedup to ensure idempotency on re-run
   - Runs once via a HM activation script or as a manual one-shot

## Scope

- **In**:
  - Cavemem v0.2.1 vendored package + 3 cherry-picked patches in overlay
  - Home-manager module with declarative settings.json + plugin file +
    mcphub registration + opencode.json wiring
  - Configurable embedding provider (4 options); default Xenova local
  - One-shot custom SQLite-direct importer for existing 111 transcription +
    91 summary notes
  - AGENTS.md restructure (remove transcription/summary write rules; keep
    memory rules)
  - vault-curator.md update for new vault topology
  - opencode wrapper hard-fail extension for cavemem health check
  - Smoke tests for the three patches (#14, #39, #25 verification)
  - Documentation: a memory note explaining the new split and how to
    troubleshoot
- **Out**:
  - The synthesizer subagent itself (vault-synthesizer-agent spec)
  - The orchestration command (memory-sync-cli spec)
  - sqlite-backup target extension (existing-spec update tracked separately)
  - Cross-host cavemem sync (cavemem #33 is upstream-deferred)
  - Auto-scheduled cavemem maintenance (compaction, vacuum, etc.)
  - Patching cavemem bugs unrelated to our integration (#11/#18/#20/#28/#37)

## Boundary Candidates

- **Overlay package vs HM module**: package builds the binary; HM module
  configures and wires it. Clean seam; could be reviewed in two PRs if
  the spec implementation grows large.
- **Settings.json shape vs plugin file shape**: settings.json is JSON-config;
  the plugin file is JavaScript shipped to opencode's plugin loader. Both
  emitted by HM but from different source paths (settings is interpolated
  from HM options; plugin is a vendored .js file copied verbatim).
- **AGENTS.md edit vs vault-curator.md edit**: Both are documentation
  changes but in different files with different audiences. Could be one
  task or two; group together since both reflect the same conceptual change.
- **Importer is its own seam**: The migration is a one-shot operation
  separate from steady-state cavemem operation. Could be a separate spec
  if it grows complex; the SQLite schema is small enough to keep here.

## Out of Boundary

- Designing or implementing the synthesizer subagent
- Designing or implementing the memory-sync orchestration command
- Adding cavemem.db to the sqlite-backup target list (separate existing-spec
  update)
- Generalizing the importer to other memory tools (this importer reads .md
  files in our vault format only)
- Building a roundtripping export from cavemem back to .md (out of scope;
  user has not asked for this)

## Upstream / Downstream

- **Upstream**:
  - `mcp-secrets-sops-nix` spec — IF the user later switches embedding
    provider to OpenAI, the API key would flow through that spec's secret
    pipeline. Not a hard dependency for the default Xenova local config.
  - `home-manager/mcp/default.nix` — cavemem joins the mcphub server set
    here.
  - `overlays/mcp-servers.nix` — the patched cavemem package likely lands
    here (or in a sibling `overlays/cavemem.nix`).
  - `home-manager/common/opencode.nix` — health-check extension hooks in
    here (lines 38-46 today).
  - Existing memory note `memories/2026-05-09-cavemem-architecture.md` is
    the architecture reference for what cavemem actually is.
- **Downstream**:
  - `vault-synthesizer-agent` spec depends on cavemem MCP being present
    and observations being non-empty.
  - `memory-sync-cli` spec depends on the synthesizer being available.
  - `sqlite-backup` existing-spec extension depends on the dataDir path
    being fixed by this spec's HM module.

## Existing Spec Touchpoints

- **Extends**: None directly (this is a new spec; existing-spec touchpoint
  to sqlite-backup is tracked separately under "Existing Spec Updates" in
  the roadmap).
- **Adjacent**:
  - `mcp-secrets-sops-nix`: for OpenAI embedding API key delivery if/when
    the user opts into that provider. The default Xenova local provider
    needs no secret.
  - `cc-sdd-integration`: precedent for a Nix-packaged CLI tool with
    declarative HM wiring (the `cc-sdd-init` shell command and the templates
    materialization pattern).
  - `sqlite-backup`: cavemem.db will become a backup target after this
    spec lands.

## Constraints

- **macOS-only verification**: All target hosts are nix-darwin; we don't
  validate Linux or Windows code paths.
- **Node version**: stay on a Node version that better-sqlite3's bundled
  bindings support. Track if/when the nodejs overlay bumps past Node 24.
- **No imperative installer**: The upstream `cavemem install` writes to
  `~/.config/opencode/opencode.json` and generates a plugin file. That
  fights HM. Our HM module replaces both.
- **Patches must be reviewable**: Apply via Nix `patches = [...]` referring
  to `.patch` files in the overlay tree, not via in-line `substituteInPlace`
  unless trivial. Each patch file documents the upstream PR it cherry-picks.
- **Importer is idempotent**: Re-running `cavemem-import-vault` against an
  already-populated DB must not duplicate rows. Use `content_hash` UNIQUE
  index on observations table (cavemem's schema doesn't enforce this; we
  add it via a `PRAGMA user_version` migration in the importer).
- **No regression of existing memory workflow**: Memory creation rules in
  AGENTS.md must remain intact. The synthesizer agent (next spec) will
  reuse them verbatim.
- **opencode hard-fail invariant**: If cavemem MCP is down, opencode must
  refuse to start, matching the obsidian invariant. This is non-negotiable
  because once we restructure AGENTS.md to expect cavemem ambient capture,
  a missing cavemem means no transcription/summary at all.
