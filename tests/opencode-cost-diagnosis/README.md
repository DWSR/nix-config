# opencode-cost-diagnosis — tests

Test suite for the `opencode-cost-report` CLI defined in spec
`.kiro/specs/opencode-cost-diagnosis/`. This directory is populated
incrementally:

- **Task 1.6 (this directory's creation)** — landed the shared
  fixture DB and the `node:test` runner entry point. No `.test.js`
  files yet.
- **Tasks 6.1 / 6.2** — will add the first `*.test.js` files (unit
  tests for attribution / tokenizer math; integration tests of the
  CLI end-to-end against the fixture).

## Layout

```
tests/opencode-cost-diagnosis/
├── README.md                          # this file
├── package.json                       # `main: "run.js"` — see below
├── run.js                             # test-runner entry point (both modes)
└── fixtures/
    └── opencode-stable.db             # synthetic opencode-shaped SQLite DB
```

`package.json` exists solely to give Node's CommonJS module
resolution a `main` entry pointing at `run.js`, so that
`opencode-cost-diagnosis-node --test tests/opencode-cost-diagnosis/`
(directory mode — Node 22's `--test` flag treats its argument as a
module specifier, not a directory glob) resolves to a runnable file
instead of erroring with `MODULE_NOT_FOUND`. It declares no
dependencies and `npm install` is never expected to run here. See
`run.js`'s header for the full directory/standalone mode-selection
rationale.

## The fixture

`fixtures/opencode-stable.db` is a synthetic, deterministic
opencode-shaped SQLite database generated by
`scripts/opencode-cost-diagnosis-test-fixture.js`. It mirrors the
opencode subset documented in `design.md` lines 855–925 plus the
pinned `data_migration` row.

**Topology** (9 sessions; 3 roots; 6 descendants):

```
ses_root_a (build, /Users/test/project-a)
├── ses_root_a_child_0
│   └── ses_root_a_child_0_sub_0
└── ses_root_a_child_1
ses_root_b (general, /Users/test/project-b)
├── ses_root_b_child_0
│   └── ses_root_b_child_0_sub_0
└── ses_root_b_child_1
ses_root_c (explore, /Users/test/project-c)   ← no children
```

**`data_migration`** contains the single v1-baseline row
`session_usage_from_messages` at the timestamp pinned in the fixture
script. Adding, removing, or renaming this row will cause the
SQLite Reader (task 2.1) to throw `SchemaDriftError` against this
fixture, which is the test surface for the schema-drift detection
path.

**Token / cost constants** (per assistant message — drive the test
assertions in 6.1/6.2):

| Session class | `tokens.input` | `output` | `reasoning` | `cache.read` | `cache.write` | `cost`  |
|---------------|---------------:|---------:|------------:|-------------:|--------------:|--------:|
| root          | 10000          | 500      | 100         | 5000         | 1000          | 0.05    |
| child / grandchild | 2000      | 200      | 50          | 1000         | 200           | 0.01    |

## Regenerating the fixture

The fixture is committed to the repo. Regenerate only when the
schema changes or new test scenarios require additional sessions /
messages / parts. The script is deterministic — re-running produces
a byte-identical file (verify via `sha256sum`):

```sh
opencode-cost-diagnosis-node \
  scripts/opencode-cost-diagnosis-test-fixture.js

sha256sum tests/opencode-cost-diagnosis/fixtures/opencode-stable.db
# ⇒ b0dd8b65550dd3e2f6b17fee7b81a9de059319bc81700beee5f8d92be61ff99f
#   (as of the topology recorded above; will change if the fixture
#    script changes, but re-running the unchanged script must
#    reproduce the same hash)
```

The wrapper is `scripts/opencode-cost-diagnosis-node.nix` from Task
1.4 and is on `$PATH` whenever
`programs.opencode-cost-diagnosis.enable` is true (which is the
default on both nix-darwin hosts via
`home-manager/common/default.nix`).

## Running the tests

Two equivalent invocations, both via the same wrapper:

```sh
# Recommended — directory mode, uses node:test's built-in globber:
opencode-cost-diagnosis-node --test tests/opencode-cost-diagnosis/

# Programmatic — useful for CI scripts wanting a single file target,
# and the natural target for the smoke-test in Task 6.3:
opencode-cost-diagnosis-node tests/opencode-cost-diagnosis/run.js
```

While no `*.test.js` files exist yet, both commands exit 0 with
"tests 0".
